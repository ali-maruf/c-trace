## Preliminary fields (paste-ready)

**Project name:** C-Trace

**One-line pitch:** C-Trace turns a factory's utility bills into a verified, auditable carbon ledger, and proves the
reductions that unlock green finance. Every tonne traces back to a bill.

**Domain / challenge:** ClimateSphere AI / CarbonIQ

**Problem statement:**
Bangladesh's export garment factories are being asked for carbon data by the brands they supply, by banks under Bangladesh
Bank's sustainable finance rules, and by regulators (BSEC ESG disclosure). The data exists only on paper: gas, electricity
and diesel bills, many in Bangla, some photographed. Today it is typed into spreadsheets by hand, errors are invisible (one
dropped digit on one gas bill in our demo hides 579 tCO₂e), and claimed savings can't be proven, so factories can't
borrow against them. Generic carbon calculators assume clean data and produce numbers nobody can audit.

**Proposed solution:**
C-Trace is an MRV (measurement, reporting, verification) platform with one rule: AI reads and explains; deterministic code
calculates.
1. *Read:* bills (PDF/photo, English or Bangla) are extracted with verbatim evidence, personal data redacted; implausible
   values (e.g. a tariff 10× the factory's norm) are flagged with a suggested correction a human must accept.
2. *Calculate:* quantity × a versioned, cited emission factor. Every ledger row keeps the bill's SHA-256, the factor
   version and source, and the arithmetic.
3. *Verify:* the C-Trace Verifier (gradient-boosted model, conformal 90% band, Shapley drivers, fairness-calibrated)
   predicts what the factory *should* have used from production, NASA POWER weather and its assets, and flags months that
   don't fit.
4. *Prove reductions:* an IPMVP Option C baseline that must pass ASHRAE Guideline 14 limits before a saving is "verified";
   a reviewer signs it and gets a certificate.
5. *Report and share:* buyer, IFRS S2 (lender) and BSEC formats from the same data; expiring, revocable share links; a
   Bangla/English Copilot whose every number is checked against the verified data.

**Target user:** Sustainability and compliance managers at Bangladeshi export garment factories (first), then the brands'
supplier-sustainability teams and the banks' green-finance desks who receive the data.

Retrieval times and licences: `data/public/PROVENANCE.json`.

**Personal data:** none in the demo (fictional). For real bills, account holder names, phone numbers and addresses are
redacted before any text is sent to a model or stored as evidence; the eval set includes a trap bill for this, with 0 leaks.

**Foundation models:** Anthropic Claude (Haiku 5.5 for extraction, escalating to Sonnet 5.5 below 0.7 confidence; Sonnet 5.5
for report narratives and the Copilot), called only when `ANTHROPIC_API_KEY` is set. Models never produce an emissions
number: they return printed text with evidence; code parses, checks and calculates; every LLM sentence passes a number
guard. Without an Anthropic key, C-Trace can use OpenAI's open-weight **gpt-oss-120b** through any OpenAI-compatible
host (free tier on OpenRouter), under the same rules; it reads text only, so photos still need Claude or a vision model.
With no key at all it runs **offline** (rules-based extraction, template narratives, intent-based Copilot). The demo
factory's 65 sample bills always use the deterministic parser.

**Own models:** C-Trace Verifier v2 (scikit-learn HistGradientBoosting + quantile scale model + split-conformal band).
Held-out metrics, fairness table and limitations: [models/MODEL_CARD.md](../models/MODEL_CARD.md).
